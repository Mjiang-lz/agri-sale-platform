# M6 平台治理 · 接口约定

> 归属：P1 李官杏（后端） / P4 蒋柳芝、P5 陈永春（管理后台页面）
> 依据：《软件需求规格说明书》2.3、2.8、2.9；《概要设计说明书》3.4 数据字典
> 状态：后端已实现并通过冒烟，前端按本表对接即可

所有接口统一返回 `Result<T>`：

```json
{ "code": 200, "message": "操作成功", "data": {} }
```

`code` 取值：`200` 成功、`400` 参数错误、`401` 未登录或登录失效、`403` 无权限、`404` 资源不存在、`500` 业务失败。
分页接口的 `data` 为 MyBatis-Plus 分页结构：`{ total, current, size, records }`。

**所有接口都需要带 `Authorization: Bearer <token>`。** 用户身份一律从登录态取，请求体里不要也不需要传 `userId` / `operatorId`。

## 一、M1 登录返回角色菜单（已改动）

`POST /api/auth/login` 的 `data` 新增两个字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `roleId` | number | 角色主键 |
| `menuPerms` | string | 菜单权限标识，英文逗号分隔 |

前端按 `menuPerms` 渲染侧边栏，即实现「不同角色看到的菜单不同」。当前取值：

| 角色 | menuPerms |
| --- | --- |
| 农户 | `home,trade,finance,expert,user` |
| 采购方 | `home,trade,expert,user` |
| 专家 | `home,expert,user` |
| 银行用户 | `home,finance,user` |
| 管理员 | `dashboard,audit,user,finance` |

`GET /api/user/profile` 同样返回 `roleId` 与 `menuPerms`，用于刷新页面后重新渲染菜单。

> 菜单权限只控制「前端显示什么」，不构成安全边界。越权判定始终在后端服务层。

## 二、用户管理（管理后台 · 用户管理页）

### 1. 用户分页列表

`GET /api/admin/users`

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `roleId` | number | 否 | 按角色筛选 |
| `keyword` | string | 否 | 按真实姓名或手机号模糊匹配 |
| `status` | number | 否 | `1` 正常 / `0` 停用 |
| `pageNum` | number | 否 | 默认 1 |
| `pageSize` | number | 否 | 默认 10 |

`records` 每项字段：`userId`、`phone`、`realName`、`avatarUrl`、`roleId`、`roleName`、`status`、`createTime`。
**不返回 `password`。**

### 2. 启用 / 停用账号

`PUT /api/admin/users/{userId}/status`

```json
{ "status": 0 }
```

### 3. 调整用户角色

`PUT /api/admin/users/{userId}/role`

```json
{ "roleId": 2 }
```

### 4. 角色下拉列表

`GET /api/admin/roles` → `data` 为数组，每项 `roleId`、`roleName`、`menuPerms`、`description`。
角色列表从库中取，**前端不要硬编码**。

### 约束（前端需据此做提示，后端已强制）

- 不能停用当前登录的管理员自己；
- 系统至少保留一名启用状态的管理员，把最后一个管理员停用或改成其他角色都会被拒绝；
- 目标角色必须是已存在的角色；把用户改成他当前的已有角色会被拒绝；
- 本模块**不提供删除用户**，只做停用。

## 三、数据看板（管理后台 · 仪表盘）

`GET /api/admin/dashboard/statistics`

| 字段 | 说明 |
| --- | --- |
| `userTotal` | 用户总数 |
| `productTotal` / `productOnSale` | 商品总数 / 在架数 |
| `demandTotal` | 求购需求总数 |
| `orderTotal` | 订单总数 |
| `financeApplyTotal` / `loanGroupTotal` | 融资申请总数 / 联合贷款小组总数 |
| `knowledgeTotal` / `commentTotal` | 知识条目数 / 评论数 |
| `pendingAuditTotal` | 待审核内容合计（商品 + 知识 + 评论） |
| `pendingFinanceTotal` | 待审批融资数（状态为「已推送银行」） |
| `roleUserDistribution` | `[{ name: 角色名, count }]` |
| `financeStatusDistribution` | `[{ name: 申请状态, count }]`，6 个状态齐全，数量为 0 也保留 |
| `auditStatusDistribution` | `[{ name: 待审核/已通过/未通过, count }]` |
| `newUserTrend` / `newOrderTrend` / `newFinanceTrend` | 近 7 日（含今天）按天新增，`[{ date: "yyyy-MM-dd", count }]`，无数据的日期补 0 |
| `generatedAt` | 统计生成时间 |

全部为实时统计，无缓存。

## 四、融资管理

### A. 银行侧（银行用户）

`GET /api/loan-admin/applies?status=` —— 查询已推送至银行侧的融资申请。
不传 `status` 时返回全部已推送的申请（`push_time` 非空）。

`POST /api/loan-admin/applies/{applyId}/approve`

```json
{ "approvalResult": "通过", "loanAmount": 60000, "approvalOpinion": "经营稳定，准予放款" }
```

- `approvalResult` 只能是 `通过` 或 `不通过`；
- 通过时 `loanAmount` 必填且须 > 0，**不得超过申请额度**；
- 不通过时 `approvalOpinion` 必填；
- 只允许对状态为「已推送银行」的申请审批，重复审批会被拒绝。

审批成功后：写入 `t_approval` 流水，申请状态回写为「审批通过」或「审批未通过」。

### B. 管理员只读台账（管理后台 · 融资管理页）

`GET /api/admin/finance/applies?applyStatus=&keyword=&pageNum=&pageSize=`

- `applyStatus` 按申请状态筛选，`keyword` 按申请编号或农户姓名模糊匹配；
- 管理员**只能看不能批**，审批动作调用 `A` 组接口会返回 403。

`records` 每项字段：

| 字段 | 说明 |
| --- | --- |
| `applyId` / `applyNo` | 申请主键 / 申请编号 |
| `applyAmount` / `applyTerm` / `applyPurpose` | 申请额度 / 期限（月）/ 资金用途 |
| `applyStatus` / `applyTime` / `pushTime` | 申请状态 / 提交时间 / 推送银行时间 |
| `farmerId` / `farmerName` / `farmerPhone` / `farmerMainProduct` | 申请农户信息 |
| `loanProductId` / `loanProductName` | 贷款产品 |
| `approvalResult` / `loanAmount` / `approvalOpinion` / `approvalTime` | 审批结论（未审批时为空） |

`apply_status` 取值严格按数据字典：`待匹配`、`已组建小组`、`已推送银行`、`审批通过`、`审批未通过`、`已放款`。
