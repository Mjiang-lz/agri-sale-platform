# 方案：专家问答页接入 DeepSeek AI 助手

> 状态：**待评审**（未提交、未实施）
> 提出日期：2026-10-14
> 关联需求：「计划给专家问答页面接一个 ai，用 deepseek 的 APIkey」

---

## 0. 一条硬约束：API Key 绝不能进前端

前端的任何 `VITE_*` 变量都会在**构建时被内联进 JS 产物**。把 DeepSeek key 放进前端 = 把它公开在
`/app/assets/*.js` 里，任何人打开浏览器开发者工具就能读走，而落地页是**无登录**的公开页面。

所以只有一条路：**后端代理**。浏览器只与本站的 `/api/ai/**` 通信，key 只存在于服务器进程的内存中，
既不进仓库、不进前端产物、也不出现在任何响应体里。

## 1. 现状（已核对）

| 项 | 现状 | 对方案的影响 |
|---|---|---|
| 后端 | Spring Boot **4.0.1** / Java 17 | `RestClient` 已在 `spring-web` 里，**零新增依赖** |
| 鉴权 | 手写 `LoginInterceptor` + `PublicEndpoints` 白名单（按「方法+路径」双条件） | 新接口默认需登录，**不必也不该**进白名单 |
| 配置范式 | `FileStorageProperties` + `@ConditionalOnProperty`（OBS 那套） | **照抄**：开关默认 `false`、密钥走环境变量、仓库保持「clone 下来就能跑」 |
| 可复用素材 | `t_knowledge`（农技知识，仅 `已通过` 对外）· `t_question` / `t_answer` | 知识库可作为「回答依据」喂给模型 |
| 前端 | 专家侧 `ExpertAnswerPanel.vue`（答复弹窗）· 农户侧 `Qa.vue`（提问卡片） | 两个候选落点 |

### 一个刚修好的前置条件

第 2 条需求刚修掉了 `request.js` 里「`code:500` 一律翻译成『服务端异常，重试无效』」的旧口径。
现在后端只要给出**具体**文案，前端就**原样透出**。这意味着 AI 的降级提示可以说人话
（「AI 助手今天额度用完了」），而不是被统一翻译成一句让用户去重试、去联系管理员的怪话。

## 2. 模型与成本（按官方定价页核对，2026-10-14）

> ★ 旧模型名 **已于 2026-07-24 停用**：`deepseek-chat` / `deepseek-reasoner` 现已返回错误。
> 当前可用：**`deepseek-flash`**（= DeepSeek-V4.1-Flash）与 `deepseek-v4-pro`。
> BASE URL（OpenAI 兼容格式）：`https://api.deepseek.com`

| 模型 | 输入·缓存未命中 | 输入·缓存命中 | 输出 | 并发 |
|---|---|---|---|---|
| `deepseek-flash` | 1 元（空闲）/ 2 元（高峰） | 0.02 / 0.04 | 4 元 / 8 元 | 2500 |
| `deepseek-v4-pro` | 4.5 / 9.0 | 0.15 / 0.30 | 13.5 / 27.0 | 500 |

单位：元 / 百万 tokens。高峰时段 = 周一至周五（不含法定节假日）**9:00–12:00 与 14:00–18:00**（北京时间），
其余时段及节假日全天为**空闲时段，半价**。

### 单次问答成本估算（`deepseek-flash`、非思考模式）

| 组成 | 估算 tokens |
|---|---|
| 系统提示词（角色 + 输出规范） | ~700 |
| 知识库 Top3 参考 | ~1200 |
| 用户问题 | ~200 |
| 输出（≤800 上限，实际约 500） | ~500 |

- 高峰：`2500/1e6 × 2 + 500/1e6 × 8` ≈ **¥0.009 / 次**
- 空闲：`2500/1e6 × 1 + 500/1e6 × 4` ≈ **¥0.0045 / 次**

按演示量级（每天 100 次）估：**约 ¥0.45–0.9/天，¥14–27/月**。

★ **建议不开思考模式**：思考链要多花 2–3 倍输出 token，延迟从 1–3 秒升到 10–30 秒，
而农技建议这类任务不需要长链推理。省下来的钱比提升的质量更实在。

## 3. 后端设计

### 3.1 新增文件

```
backend/src/main/java/com/rxt/config/AiProperties.java          # @ConfigurationProperties("rxt.ai")
backend/src/main/java/com/rxt/ai/AiChatClient.java              # 出网调用（RestClient，含超时）
backend/src/main/java/com/rxt/ai/AiRateLimiter.java             # 每用户 + 全局滑动窗口
backend/src/main/java/com/rxt/ai/AiPrompts.java                 # 提示词模板（集中一处，便于评审与迭代）
backend/src/main/java/com/rxt/service/AiAssistantService.java   # 知识库检索 + 组装 + 降级
backend/src/main/java/com/rxt/controller/AiController.java      # /ai/**
backend/src/main/java/com/rxt/dto/AiConsultDTO.java
backend/src/main/java/com/rxt/vo/AiAnswerVO.java                # {content, sources[], model, usage}
```

### 3.2 配置（`application.yml` 新增段，全部留空或走环境变量）

```yaml
rxt:
  ai:
    # 与 OBS 同一条纪律：默认 false，仓库保持「clone 下来就能跑」；
    # 队友没有 key 也能起后端，问答页只是不显示 AI 入口。
    enabled: ${RXT_AI_ENABLED:false}
    base-url: ${RXT_AI_BASE_URL:https://api.deepseek.com}
    # ★ 留空。真实 key 只从环境变量或 application-local.yml（已 gitignore）注入。
    api-key: ${RXT_AI_API_KEY:}
    model: ${RXT_AI_MODEL:deepseek-flash}
    connect-timeout-ms: 3000
    read-timeout-ms: 30000
    max-output-tokens: 800
    temperature: 0.3
    # 限额：单用户 / 全体，均为滑动窗口
    per-user-per-hour: 20
    per-user-per-day: 200
    global-per-day: 500
```

### 3.3 接口

| 方法 | 路径 | 谁可用 | 作用 |
|---|---|---|---|
| `GET` | `/api/ai/status` | 登录用户 | 返回 `{enabled, model}`。前端据此决定**入口显不显示** |
| `POST` | `/api/ai/qa/draft` | 专家 | 传 `{questionId, hint?}` → 返回草稿 + 引用来源 |
| `POST` | `/api/ai/qa/consult` | 农户 | 传 `{content}` → 返回参考意见（本期可选） |

★ 用**独立的 `/ai` 前缀**，不挂到 `/expert/qa/` 下面 —— 后者在 Controller 层面套着既有的
`requireRole` 语义，混进去容易被误伤；`/ai` 的鉴权自己写清楚。

★ `/api/ai/status` 需登录，**不进 `PublicEndpoints` 白名单**。白名单是攻击面，不是便利开关。

### 3.4 提示词与上下文（这是质量的关键，也是可评审的部分）

**角色与输出规范**（写在 `AiPrompts.java`，集中一处便于改）：

- 你是农业技术顾问，只回答种植/养殖/病虫害/农资使用等农业生产问题；
  与农业无关的请求（写代码、闲聊、政治）礼貌拒绝并引导回农业。
- 输出固定三段：**现象判断 → 处置建议 → 注意事项**。建议要具体、可执行，涉及时间与剂量要落到数字。
- **不确定就说不确定**，并建议联系当地农技站或提交给平台专家，不要编造。
- 涉及用药：不给未经核实的农药品种与剂量，必须提示「先小范围试、按标签剂量、
  注意安全间隔期与个人防护」。

**上下文增强（轻量检索）**：

1. 从用户问题里取关键词，检索 `t_knowledge` 中 `audit_status='已通过'` 的条目，取 Top 3；
2. 拼成「以下是平台已审核的农技知识，优先据此回答；引用时注明标题」段落塞进 system；
3. `AiAnswerVO.sources` 带上被引用的知识标题与 id，前端在草稿下方显示
   「参考了平台知识：《××》」，让回答**有依据、可追溯**。

★ 检索时注意两件事：
- MyBatis-Plus 里多个 `or` **必须用 `and(...)` 包住**，否则 OR 优先级低于 AND，
  会冲掉 `audit_status='已通过'` 这个条件（项目里踩过，属静默越权）。
- `t_knowledge.author_id` 存的是 `t_expert.expert_id`，**不是 user_id**，别按字段名想当然。

**贴合领域**：把当前专家的 `expertDomain` 传给模型，让口吻与侧重符合该领域。

### 3.5 限额（防「一个演示账号烧掉 key」）

`AiRateLimiter` —— 内存滑动窗口，单实例足够：

- 每用户 20 次/小时、200 次/天
- 全局 500 次/天（兜底，防止有人批量刷）

超限返回具体文案：「AI 助手今日额度已用完，请稍后再试，或直接把问题提交给专家」。
★ **不引入 Redis**：本项目是单机部署（宝塔 + 单 JVM），为一个限流器加中间件不划算；
真要上多实例时再换，届时把实现收在 `AiRateLimiter` 一个类里即可。

### 3.6 错误与降级

| 情况 | 对用户的表现 | 真实原因去向 |
|---|---|---|
| `enabled=false` 或 key 为空 | `/ai/status` 返回 `enabled:false` ⇒ 前端**整块隐藏入口** | — |
| 上游超时 | 「AI 助手暂时忙不过来，请稍后重试，或直接提交给专家」 | 日志 |
| 上游 401 / 402（key 失效、余额不足） | **同一句通用话术** | 只进日志 |
| 上游返回空或格式异常 | 同上 | 日志 |
| 命中限额 | 「今日额度已用完…」 | 日志 |

★ 「余额不足」这类运维信息**绝不能**透给农户 —— 后端只回通用话术，真实原因写日志。

★ **前端入口靠 `/ai/status` 决定显不显示**，而不是放一个点了报错／点了没反应的按钮。
这正是第 3 条需求（落地页资讯「看起来能点却点不动」）的教训：**宁可没有，也不要给假的**。

### 3.7 ★★ 最关键的一条设计决定：AI 输出不进库、不发帖

AI 只产出**草稿文本**，填进专家的答复输入框；**只有专家点「提交回答」才落 `t_answer`**。

理由三条，都不打算妥协：

1. **责任在专家**。平台现有的内容审核只覆盖 PRODUCT / KNOWLEDGE / COMMENT，**不覆盖回答**；
   AI 直接发布等于出现一段无人审阅、以平台名义对外的农技建议 —— 涉农用药建议出错是有实际后果的。
2. **绕开一个没有答案的问题**：「AI 生成的内容要不要过审核流」在本项目里没有既定口径，
   而「AI 只做草稿」让这个问题根本不需要被回答。
3. **署名是人**。出错时是专家署名，平台与专家都有动力看一眼再发。

因此草稿区必须显式标注：**「AI 生成，仅供参考，需你确认后提交」**。

## 5. 上线要做的三件事

1. **服务器能出网**到 `api.deepseek.com:443`（宝塔/腾讯云默认出网放行，无需改入站规则）。
2. **启动命令追加参数**（★ 所有 `-D` 必须在 `-jar` **之前**）：
   ```
   -Drxt.ai.enabled=true -Drxt.ai.api-key=<你的 key>
   ```
   或在宝塔启动脚本里 `export RXT_AI_API_KEY=<你的 key>`。
3. **密钥不落盘到仓库**：不改 `application.yml` 的默认值、不写进 `docker-compose.yml` /
   `.env.example`（这两个是入库的）。只走环境变量或 `application-local.yml`（已 gitignore）。
   这与 OBS 的 AK/SK、`rxt.jwt.secret` 是同一条既有纪律（《概要设计说明书》§8.3 要求密钥与代码分离）。

## 6. 本期建议不做（写明原因，避免后面被当成漏做）

| 不做 | 原因 |
|---|---|
| 流式输出（打字机效果） | 本项目所有接口都是 `Result<T>` 同步包装，上 SSE 要另开一条链路；而 500 字以内答复总耗时 1–3 秒，收益小。可作 v2 |
| 多轮对话记忆 | 问答页是「一问一答」；带历史会让 token 成倍增长，还容易把上一个问题的错误结论带进下一个 |
| 向量检索（真 RAG） | 本期关键词检索 `t_knowledge` 已够用；上向量库需额外组件，与本项目「单机 + MySQL」的部署形态不匹配 |
| 图片识别（拍叶片问诊） | `deepseek-flash` 虽支持图像理解，但涉及上传/存储/隐私与成本评估，建议单独立项 |

## 7. 验收口径（防「接口 200 但其实没接上」）

- **正向**：专家点「AI 起草」→ 输入框出现三段式草稿 → 草稿下方显示引用来源 → 提交后 `t_answer` 里是**专家改过的**内容。
- **反向对照（必须做）**：把 `rxt.ai.enabled` 关掉重启 → `/ai/status` 返回 `enabled:false` → **AI 按钮消失**。
  没有这条对照，「按钮不显示」与「按钮本来就坏的」在输出上长得一模一样。
- **降级**：故意用一个失效 key 起服务 → 页面提示通用话术，**且不能出现** `401` / `余额不足` / `api.deepseek.com` 等字样。
- **限额**：连续调用超过阈值 → 返回额度用完提示，**且不产生新的上游计费**（看日志里 `[ai]` 行数不变）。
- **密钥不泄露**：三端产物里 `grep -r 'sk-' dist/` 必须为空。

## 8. 实施记录（2026-10-14，已落地并实测）

### 8.1 与本文档不同的两处（按评审意见调整）

| 项 | 原方案 | 实际采用 | 原因 |
|---|---|---|---|
| 落点 | 专家侧「AI 起草回答」 | **农户侧「问 AI 助手」**（与「问平台专家」二选一） | 产品判断：AI 更适合做农户的即时分流，而不是替专家起草 |
| 平台知识库 | 关键词检索 `t_knowledge` 做参考 | **不接，纯模型回答** | 评审意见；实现更简单，也少一处「AI 说的和平台已审核知识不一致」的风险 |

模型与档位按原方案：`deepseek-flash` + **非思考模式**。

### 8.2 ★★ 实施中踩到的两个坑（都在本文档之外，值得单记）

**坑一：思考模式默认打开，输出预算被吃光。**
DeepSeek 的思考模式**默认 `enabled`、`effort` 默认 `high`**，而**思维链与最终回答共用同一个
`max_tokens`**。不显式关掉时的症状极具误导性：

```
HTTP 200  ·  上游无任何报错  ·  completion_tokens 正好打满 (=800)  ·  但 content 是空字符串
```

页面上什么都没有，日志里也看不出异常。更要命的是**它在接口层很难被发现** ——
HTTP 状态正常、`code` 也确实是 500（我们的兜底话术），所以「接口报错了」这个断言会过，
而人看到的只是「AI 助手暂时忙不过来」，真实原因藏在日志的一句「上游返回结构不合法」里。
修法：请求体显式带 `{"thinking": {"type": "disabled"}}`。
另在日志里把「content 为空但 reasoning_content 非空」单独认出来、直接点明原因 ——
否则下一个排查的人会去怀疑网络、怀疑 key、怀疑参数名，唯独不会想到这条。
注：思考模式下 `temperature` **不生效**（官方文档明确），所以只有关掉思考，本文档 §3.4 的
`temperature: 0.3` 才有意义。

**坑二：默认会输出 Markdown，星号直接露给农户看。**
模型天然用 `**现象判断**` 这种写法，而页面按纯文本渲染 —— 截图里能直接看到 `**` 字面量。
修法：在提示词里明确「不要使用任何 Markdown 记号，要强调就用【】或「」」。
不引 Markdown 渲染器的理由：多一个依赖、多一个 XSS 面，而农技建议本来是纯文字，用不上。

### 8.3 验收结果

| 组 | 断言 | 结果 |
|---|---|---|
| 关闭态（18081 另起实例，不动主栈） | 鉴权/状态/文案/路径存在性/参数校验 | **10 / 10** |
| 开启态（真实调用） | 状态、真回答、带上下文追问、不泄露上游 | **17 / 17** |
| 边界 | 限额拦截 + **换用户仍可提问**（证明限的是「每人」）+ key 失效降级 | **18 / 18** |
| 浏览器（CDP，含反向对照） | 入口显隐、切模式、真回答上屏、**拦掉 /ai/status 后入口整块消失** | **19 / 19** |

其中两条是「硬数字」而非「看起来对」：

- **历史收口**：100 条共 36000 字符的历史，与只带服务端会保留的那 6 条（2160 字符），
  实测 input token **完全相同**（`in=1567` 对 `in=1567`）。
- **密钥不泄露**：三端产物里按真实密钥形态 `sk-[A-Za-z0-9_-]{20,}` 检索 **0 命中**。
  ★ 注意不能用 `grep 'sk-'` —— 它会命中 `mask-color` / `ask-tip` / `ask-mode` 这类子串，
  全是假阳性。

### 8.4 上线仍需人工做的两步

1. 服务器启动命令加：`-Drxt.ai.enabled=true -Drxt.ai.api-key=<key>`（★ 必须在 `-jar` **之前**）。
2. 确认服务器能出网到 `api.deepseek.com:443`。
