# 接口约定 — 公共文件上传

> 面向：前端（`frontend-web` / `frontend-admin`）、需要上传图片的模块负责人
> 实现：`controller/CommonController`、`storage/*`（`LocalFileStorageServiceImpl` / `ObsFileStorageServiceImpl`）
> 依据：《概要设计说明书》§6 接口清单「公共 → 文件上传」、§8.4 文件上传安全要求

---

## 一、三个必知概念

**① 一个接口覆盖三类图片，靠 `bizType` 区分。**
不按模块分开接口（不是 `/trade/upload`、`/expert/upload` 各一个）。`bizType` 是一张白名单，
决定文件落在哪个目录：`PRODUCT`（商品图片）/ `KNOWLEDGE`（知识配图）/ `AVATAR`（用户头像）。
前端传目录字符串是不允许的 —— 那等于让客户端决定往存储的哪儿写文件。

**② 一次请求只传一个文件。**
商品图 1～9 张 = 调用 9 次，自己把返回的 `url` 收进数组。这样错误语义干净：
批量接口会出现「第 3 张失败但前 2 张已落库」的部分成功态，前端最难处理；
单文件上传天然是全成功或全失败。Element Plus 的 `el-upload` 默认就是「一个文件一个请求」，不需要额外适配。

**③ 返回的 `url` 可以直接塞进 `<img :src>`。**
本地兜底模式返回**相对路径** `/api/files/...`；OBS 模式返回完整 `https://<bucket>.<endpoint>/...`。
两种形式浏览器都能直接用，**前端不需要按模式写分支**。
⚠️ 唯一的差别：相对路径要拼上前端的 `baseURL`（即 `/api`），绝对地址不要拼（拼了会变成 `<域名>/api/https://...`）。
最省事的写法见下面第 6 节的 `toDisplayUrl`。

---

## 二、接口总览

| 用途 | 方法 | 路径 | 鉴权 |
|---|---|---|---|
| 上传单个文件，返回可访问地址 | `POST` | `/api/common/upload` | **需登录**（`Authorization: Bearer <token>`） |
| 读取已上传的图片（本地模式） | `GET` | `/api/files/**` | **免登录**（商品图是公开内容） |

上传是写操作，**刻意不在免登录白名单里**；免登录的只有它的读侧。
OBS 模式下文件不经后端，`GET /api/files/**` 这条映射与放行规则都**不会注册**（跟随 `rxt.obs.enabled` 开关），
此时图片地址直接指向对象存储。

---

## 三、请求

```
POST /api/common/upload
Content-Type: multipart/form-data
Authorization: Bearer <token>
```

| 字段 | 位置 | 必填 | 说明 |
|---|---|---|---|
| `file` | form-data | 是 | 文件本体。**单张 ≤ 5MB**；仅支持 jpg / jpeg / png / gif / webp |
| `bizType` | form-data | 是 | `PRODUCT` \| `KNOWLEDGE` \| `AVATAR`（**大小写不敏感**，也接受小写目录名 `product` 等；非法值 400） |

curl 示例（README 的联调方式）：

```bash
curl -X POST "http://localhost:8080/api/common/upload" \
  -H "Authorization: Bearer <token>" \
  -F "file=@/path/to/pic.png;type=image/png" \
  -F "bizType=PRODUCT"
```

## 四、响应

项目统一结构，**HTTP 恒 200**，真正的状态看 body 里的 `code`：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "url": "/api/files/product/2026/09/3f2b1c9d4e5a4b8c9d0e1f2a3b4c5d6e.png",
    "objectKey": "product/2026/09/3f2b1c9d4e5a4b8c9d0e1f2a3b4c5d6e.png",
    "size": 10362,
    "storage": "local"
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `url` | string | **前端要用的就是它**，直接作为图片地址 |
| `objectKey` | string | 存储侧相对路径，与 `url` 的区别是没有访问前缀；排查问题时按它检索 |
| `size` | number | 文件字节数 |
| `storage` | string | `local` 或 `obs`，联调时用来确认当前走哪条链路；前端可以不关心 |

## 五、错误码对照

以下全部是 **HTTP 200 + `code` 不为 200**，前端按 `code` 判断即可：

| code | 触发条件 | message |
|---|---|---|
| 401 | 没带 token / token 过期 | 登录状态已失效，请重新登录 |
| 400 | 请求不是 multipart | 请以 multipart/form-data 方式上传文件 |
| 400 | 方法不对（如用 GET 调） | 请求方法 GET 不被该接口支持 |
| 400 | 漏传表单字段 `file` | 缺少必填参数：file |
| 400 | 漏传表单字段 `bizType` | 缺少必填参数：bizType |
| 400 | 选中了 0 字节文件 | 请选择要上传的文件 |
| 400 | `bizType` 非法 | bizType 不合法：goodss（合法取值：PRODUCT、KNOWLEDGE、AVATAR） |
| 400 | 5MB < 大小 ≤ 10MB | 图片大小不能超过 5MB（当前 6.0MB） |
| 400 | 大小 > 10MB（容器级拒绝） | 上传文件过大，请压缩后重试（单张图片不能超过 5MB） |
| 400 | 文件头不是图片（含「改名冒充」） | 仅支持 jpg / jpeg / png / gif / webp 格式的图片 |
| 400 | 读取上传临时文件失败 | 图片读取失败，请重新选择文件 |
| 500 | 落存储失败（磁盘/网络异常） | 图片上传失败，请重新上传 |

> ⚠️ **两条大小上限的分工**：5MB 是「图片」这条业务规则（在图片校验里判），
> 10MB 是传输层的全局兜底（`spring.servlet.multipart.max-file-size`）。
> 两条都给了**可读文案**，不会出现「系统繁忙」这种把客户端错误伪装成服务端故障的提示。

## 六、前端典型用法

### 1. 上传（axios + Element Plus）

```js
import request from '@/api/request'

// el-upload 的 http-request 自定义上传（一个文件一个请求，与后端设计一致）
async function uploadImage(file) {
  const form = new FormData()
  form.append('file', file)          // 字段名必须是 file
  form.append('bizType', 'PRODUCT')  // 商品图传 PRODUCT

  // 注意：不要手动设置 Content-Type，让浏览器自己带上 multipart 的 boundary
  const res = await request.post('/common/upload', form)
  return res.data.url                // 拿到可访问地址
}
```

### 2. 显示（相对/绝对地址通吃）

```js
// 本地模式是 /api/files/...，OBS 模式是 https://...
export function toDisplayUrl(url) {
  if (!url) return ''
  return /^https?:\/\//i.test(url) ? url : `${import.meta.env.VITE_API_BASE || ''}${url}`
}
```

### 3. 与商品发布的衔接（M2 验收判据）

```
① 逐张调 POST /api/common/upload  → 收集 url 数组（商品图最多 9 张）
② 调 POST /api/trade/product/publish（或 PUT /api/trade/products/{id}）
   把数组放进 images 字段
③ 详情页 / 列表页用 toDisplayUrl() 渲染
```

**上传接口不写任何业务数据库** —— 它只负责把文件落到存储、返回地址；
「这张图属于哪个商品」由第 ② 步的 `images` 字段决定。所以「先传图后发布」和「先发布后补图」都能走通。

## 七、注意事项

1. **图片地址不用带 token**：`<img src>` 不会带 `Authorization` 头，也不需要带（本地模式下 `GET /api/files/**` 已免登录放行）。
2. **文件名以服务端为准**：返回的地址是 `<业务>/<年>/<月>/<32 位 uuid>.<规范扩展名>`，
   与客户端文件名无关（**后缀以文件头识别结果为准** —— 一个「后缀 jpg 实际是 png」的文件会被存成 `.png`）。
   所以不要用客户端文件名做展示或去重依据。
3. **同名不会覆盖**：uuid 命名，重复上传同一张图得到两个不同地址。
4. **`storage` 字段可自查链路**：联调时若怀疑配置没生效，看它是不是 `local`。
5. 上传目录随启动方式变化：IDEA 直接 Run 时是 `<项目根>/uploads`，
   `cd backend && mvn spring-boot:run` 时是 `backend/uploads`。两者都在 `.gitignore` 覆盖内。
